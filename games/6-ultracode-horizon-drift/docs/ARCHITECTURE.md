# HORIZON DRIFT — Architecture & module contracts  (Godot 4.7.2, GDScript, Forward+, Jolt)

A No-Man's-Sky-style space exploration game: seeded galaxy → star systems → spherical planets you can walk around, seamless space↔atmosphere↔surface,
ship + on-foot gameplay, black holes. All custom 3D models are made in Blender via MCP (docs/MODELS_SPEC.md, `assets/models/*.glb`, `ModelLib`).
Project root = `<local-path> 5.5 Effort Test\6. Ultracode Effort`. Everything is built from code: no external art, no external audio files.

## 1. Units, scales, constants
* 1 unit = 1 metre. GDScript `float` is 64-bit; `Vector3` is 32-bit → absolute positions are `DVec` (core/dvec.gd). Never keep absolute positions in a Vector3.
* Planets: radius 5–11 km (landable), moons 1.9–5.5 km, gas giants 28–45 km. Gravity 3–13 m/s². Star radius 36–90 km. Orbits 0.45–6 million m (home system: 520 km … 2800 km). Orbital speeds 180–440 m/s. Day length 8–25 min.
* Capture radius (frame switching) = 14 × radius (12× for gas giants). Atmosphere thickness (def.atmo_height) 2.5–6 km.
* Ship: ~13 m long. Walk 6 m/s, sprint 11, jetpack burst. Impulse flight up to ~450 m/s (boost ~1200), pulse drive up to ~40 km/s, atmosphere speed limit ~600 m/s (drag).
* **Camera clip planes (HARD RULE, Godot light-culler bug):** far/near ≤ 2e7. Use `Game.CAMERA_NEAR_SHIP/FAR_SHIP` (0.3 / 6e6) for the ship camera and `Game.CAMERA_NEAR_FOOT/FAR_FOOT` (0.1 / 2e6) on foot. The star is always drawn within 1.5e6 (Frame compresses it: moved closer + uniformly scaled), so it stays visible. Other bodies farther than the far plane simply vanish (fine).
* Reverse-Z is on in Forward+, so depth precision is good. Avoid huge meshes with huge vertex coordinates: build chunk meshes relative to a chunk-centre node transform.

## 2. The Frame system (most important concept) — autoload/frame.gd
Absolute coordinates (DVec, system space, star at origin, non-rotating) are converted to LOCAL coordinates (what Godot renders/collides): `local = basis * (abs - origin)`.
* **SPACE frame** (`Frame.anchor == -1`): basis = identity, origin floats and is re-centred on the focus (ship) whenever it drifts 2 km away (`_rebase`). The ship is always within ~2 km of local (0,0,0). Bodies are placed at `abs - origin`, so far things have float error ≈ 0.1 m (irrelevant at distance) while everything near the ship is precise.
* **BODY frame** (`anchor == i`): entered automatically when the focus enters body i's `capture_radius` (14 R); left again beyond 1.12×. Origin = planet centre, basis = inverse of the planet's spin ⇒ **the planet is fixed at local (0,0,0), unrotated**. Terrain, props, colliders, ship, player all use planet coordinates (≤ ~15 km ⇒ mm precision). The sun/stars/other bodies sweep across the sky instead of the planet spinning. Moons have nested frames (deepest capture sphere wins).
* Switching frames applies one rigid transform to every node in group `"frame_objects"` (ship, player, debris, free cam). Such nodes `add_to_group("frame_objects")` in `_ready` and implement `_on_frame_shift(rot: Basis, shift: Vector3, vel_offset: Vector3)` to convert their own velocity: `velocity = rot * velocity + vel_offset` (their transform is already updated). Anything that stores LOCAL positions/vectors in variables (waypoints, last positions, trails) must also convert them there or listen to `Frame.frame_changed` / `Frame.origin_shifted(shift)`.
* Frame runs LAST each frame (`process_priority = 100`): all gameplay (`_process` at priority 0) moves things first, then Frame advances `Universe.time`, switches/rebases and repositions all bodies + the sun. **Gameplay runs in `_process(dt)` (variable timestep, clamp dt to ≤ 0.05), NOT `_physics_process`** – no physics interpolation, no jitter. `CharacterBody3D.move_and_slide()` works from `_process` (it uses the idle delta). Keep camera updates in the same `_process` after the body moved.
* Body nodes are children of the `System` node (identity). Never set body transforms yourself (Frame does, including uniform scale for the compressed star). A Planet's `global_transform` may be rotated/translated (SPACE frame) or identity (BODY frame, when anchored on it).
* Helpers: `Frame.to_local(DVec)`, `Frame.to_abs(Vector3)`, `Frame.abs_dir_to_local(v)`, `Frame.anchor`, `Frame.anchor_def()`, `Frame.anchor_node()`, `Frame.sun_dir` (unit vector local space, toward the star, from the focus), `Frame.star_local`, `Frame.basis`, `Frame.register_space_object(node, pos_fn: Callable(t)->DVec, basis_fn)`.
* Global shader params (declared in project.godot): `sun_dir` (vec3), `sun_color` (color), `sun_energy` (float), `sky_basis` (mat3 = Frame.basis: inertial_dir = transpose(sky_basis) * local_dir, i.e. in GLSL `vec3 d = EYEDIR * sky_basis;`), `night_amount` (float). Frame sets sun_dir + sky_basis each frame; the sky module sets sun_color / sun_energy / night_amount.

## 4. Node tree
```
Main (scenes/main.gd)
 ├─ World (Node3D)
 │   ├─ System (StarSystem)   ← Game.load_system(): Star (StarVisual), one node per BodyDef (Planet / GasGiant / BlackHole), Extras (SystemExtras)
 │   ├─ Local (Node3D)        ← frame objects: Ship, Player, DebugFreeCam, drops
 │   ├─ SkyController         ← WorldEnvironment + sun DirectionalLight3D
 │   ├─ WeatherFX, FaunaManager
 ├─ UI (CanvasLayer 10): Hud, SystemMap, InventoryPanel, GalaxyMap, ControlsPanel, PauseMenu, MainMenu
 └─ Overlay (CanvasLayer 20): WarpEffect
```
Physics layers: 1 = terrain collision patch, 2 = static props (trees, rocks, structures), 3 = resource nodes (mining ray), 4 = ship hull (walk-around collider), 5 = player, 6 = creatures, 7 = interactables. Jolt physics, default gravity 0 (spherical gravity is applied by the player/ship code).

### M1 TERRAIN (`m1_terrain`): `world/planet/**`, `shaders/terrain*`
Cube-sphere quadtree LOD planet: 6 root faces, split by distance/screen-space error, patch grid 33×33 (or similar) with skirts (no cracks), consistent normals across chunk borders, vertex colours from the biome palette (height, slope, latitude, noise; alpha = emission mask for lava/glow), mesh vertices relative to a chunk-centre transform, threaded generation (`WorkerThreadPool`), upload budget per frame, chunk pooling/cache, horizon culling, max depth so the finest vertex spacing at the surface ≤ ~1.2 m (radius ≤ 11 km). Seamless from 1000 km (planet is a disc) to 1 m (standing on it). `height_at` per biome archetype (desert dunes, barren craters, volcanic cones + lava basins, frozen ridges/crevasses, exotic mesas/floating-spires-friendly, ocean islands, lush hills & mountains), deterministic, thread-safe, includes smooth flattening of `PoiSites` (flat sites). Terrain shader (spatial): vertex-colour albedo, triplanar detail normal/roughness noise (procedural/NoiseTexture), slope rock blend, snow/sand/emissive-lava (alpha), distance-based detail fade, receives shadows, good with the atmosphere post-process. Physics: collision patch (ConcavePolygonShape3D, layer 1) generated in a worker thread around `set_collision_focus`, `is_collision_ready`. Creates AtmosphereEffect / CloudLayer / OceanSurface / ScatterManager children per the API. Provide `water_level` per biome (lush/ocean/swamp ≥ ocean; volcanic lava; toxic acid). Verify with the free cam at 4 altitudes for ALL biomes (screenshots), plus a walk-along test that LOD never leaves holes. Keep ≥ 60 fps.
